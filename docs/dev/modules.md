# modules: The Lua modules of dev, the .dev scripts, the test runner, guide and scribe

## dev modules

The luajit modules `dev` is growing into: `dev.cli` (dispatch), `dev.verb` (the `.lua` verb contract: `chunk(ctx)`, `usage_error`, `no_args`, `die`, `show`, `need`), `dev.cmd.types` (the project type's built-ins and the command lines `dev help <verb>` prints for them), `dev.cmd.misc` (`deploy`, `guide`, `bootstrap`), `dev.cmd.tools` (`tools install` and `tools check`), `dev.cmd.box` (the `box` subcommands, the time-left text and the `ci box` call), `dev.cmd.board` (the `board` subcommands and the one place that turns a result into output and an exit code), `dev.board` (the column names and short forms, the card-id prefix match, the size label, the table lines and the `dev.board.Backend` interface the commands call), `dev.board.pomb` (that interface over curl, with the token read by `pass` and handed to curl on standard input) and `dev.cmd.connect` (`connect` and `box connect`), `dev.cmd.init` (`init`: `--type`, `--public`, `--name`, `--dry-run` and `--no-gerrit`, the `would create:`, `created:` and `skipped:` lines, the summary, the Gerrit project and remote, and the Pomb board hint) and `dev.cmd.sync` (the lint-template `sync`: `--check`, `--yes` and `-y`, the `missing:` and `differs:` lines, `up to date`, the diffs, the confirmation through `dev.ui` and `synced` or `aborted`, with `--check` and `--yes` together a usage error) and `dev.templates` (the lint set directory, the manifest, the rendering that keeps the project's text below the `lint.sh` and `deny.toml` markers, the `[workspace.lints]` block, the library-register attribute and the guide part of `docs/STYLE.md`; `sync` and `init` both call it, and `dev.pipelines` reads the `.ci/jobs.lua` and workflow texts `init` writes from `dotfiles/bin/.local/share/dev/init/`), `dev.toml` (a small TOML reader: tables and dotted tables, basic strings, integers, booleans, one-line arrays of scalars and comments, and an error naming the line for anything else), `dev.config` (`config.get(root, "a.b")` reads `~/.config/dev/config.toml` and then `<root>/.dev/config.toml` over it, `config.user("a.b")` reads the user file alone, a malformed file is `dev: <path>:<line>: <reason>` with exit 1, and as root no file is read), `dev.root` (the root gate's allowed words and the checked manifest copy), `dev.remote` (`--remote`), `dev.registry`, `dev.help` (`dev help` and the help every verb's `-h` and `--help` print, which detects the project type only for `lint`, `fmt`, `test`, `build`, `run` and `fetch`; `dev.project`'s Lua check is one `find` capped at 4 levels that skips dot directories, `node_modules` and `target` and does not follow symlinks below the root, and `dev.cli.guard` and `dev.verb` turn an `interrupted!` error into exit 130 with nothing on standard error), `dev.complete` (the hidden `__verbs`, `__subs` and `__flags` that feed shell completion, and `__topics check`), `dev.topics` (the topic files and the check behind `__topics check`), `dev.os` (quoted commands, `nap`, `capture_input` to run a command with a secret on its standard input, exec, isatty, the uid, and `kind_of`, `open_nofollow`, `fstat`, `read_fd` and `close` through ffi), `dev.release` (the session the `scripts/install-jjui.lua` and `scripts/install-pi.lua` release installers share: `--dry-run [version]` parsing, the latest-tag lookup, the platform names, `step` that runs or prints a command, and a scratch directory removed at the end. A `die` prints `  ! install-<tool>: <message>` and exits 1), `dev.term` (raw mode that is always restored, key decoding including pgup, pgdn, home and end), `dev.text`, `dev.ui` (colors, tables, bars, confirm, which wraps the consequence to the terminal width above the `[y/N]` question, and spin), `dev.ui.markdown` (one function, `markdown(text, {width, color})`, returning the text styled for a terminal: headings and bold in bold, inline code in cyan without its backticks, fenced code indented and never wrapped, bulleted and numbered lists with their indent and a hanging wrap, pipe tables with every column as wide as its widest cell, and prose wrapped at the width. A table wider than the width shrinks its widest columns, down to the longest word or 8 columns, and wraps the text inside the cells, never falling back to the raw row. `color` off drops the markers and paints nothing. `dev help` calls it with the terminal's width capped at 100 when standard output takes color, and `tests/lua/markdown_test.lua` pins both modes) and `dev.ui.picker` (up and down, ctrl-p and ctrl-n, and j and k move. Pgup and pgdn move by a window, and home and end by the list. A list taller than the screen scrolls in a window that follows the cursor, with dim `↑ n more` and `↓ n more` lines. When the context has no height, the picker reads the screen's rows from its `size` before each draw, which is 24 when `term.size` cannot read them, and `Model:lines` windows only when `ctx.height` is set. In multi mode a row with `checked` starts checked, and `required` keeps enter from finishing until a row is checked). Their tests are `tests/lua/*_test.lua`, run one file at a time by the hand-rolled runner (`luajit tests/lua/run.lua <file>`), and `tests/dev/{term,picker,confirm}.bats`, which drive a pty through `tests/dev/pty.bash`. `dev test` runs them when luajit is on PATH and prints `SKIP` for a suite that ran no case. This repo's own `dev lint`, `dev fmt` and `dev test` are `.dev/lint.lua`, `.dev/fmt.lua` and `.dev/test.lua`, with the shared code in `.dev/lua/dotfiles/checks.lua` (project verbs get `.dev/lua` on `package.path`). `dev lint` runs shellcheck, shfmt and the comment-spacing check over the bash roots, the bare-assertion check over the bats files, and stylua, selene, ast-grep and the comment checks from the style skill's `lint/lua` set over the Lua roots (the dev modules, `main.lua`, the guide modules, `tests/lua`, `scripts` and `.dev`), and `dev fmt` runs stylua over the same files with the same config. selene runs with `--no-exclude`, because the set's `exclude = [".*/**"]` would hide `.dev`. `dev test` runs every bats file, `*_test.sh` and `test-*.sh` script and `*_test.lua` suite, runs the suites in parallel (a worker pool of the core count from `nproc` or `sysctl -n hw.ncpu`, `DEV_TEST_JOBS` overrides it and 1 runs one after another, each suite in its own `TMPDIR` with its output in a file, Ctrl-C included: the scratch directory `dt.XXXXXX` sits under a short `TMPDIR` or `/tmp`, so a suite's `TMPDIR` stays under 60 characters, and a guard process in its own process group waits for dev to die, sends TERM and then KILL to every unfinished suite's group and removes the scratch directory, with `tests/dev/interrupt_test.sh` pinning it) except the pty, tmux and help-snapshot suites (`tests/dev/{term,picker,confirm}.bats`, `tests/dev/help_test.sh`, `tests/lua/help_test.lua`, `tests/tmux/conf_test.sh`, `tests/jj/land.bats` and the neomutt scripts), which run one at a time beside the pool, prints each suite's output whole with its `PASS`, `FAIL` or `SKIP` line in discovery order and a summary line, and when the uid is not 0 or the OS is not Linux it ends with `dev: the real-root cases of tests/dev/root_test.sh and tests/dev/tools_test.sh were skipped, run dev --remote test for them`.

## .dev scripts

One script per verb (`install.lua`, `uninstall.lua`, `restow.lua`, `purge.lua`, `clean.lua`, `list.lua`, `stow.lua`, `sync.lua`, `setup.lua`, ...) run through `dev <verb>`, and the subdirectories `pi/` and `antinote/` hold the Lua subcommands of `dev pi` (`install`, `save`, `diff`, `check`) and `dev antinote` (`export`, `import`, `diff`), over `.dev/lua/dotfiles/pi.lua` and `antinote.lua`. `lint.lua`, `fmt.lua` and `test.lua` are Lua verbs that run in the dev process (see the `dev.*` bullet above). The install family is `.dev/lua/dotfiles/packages.lua`: `default_deps` (the single source of truth for the default targets), `select` (the package arguments, or the defaults), `ensure_stow` (runs `scripts/install-stow.lua`, the pinned build, into `DEV_TOOLS_PREFIX` else `~/.local` when stow is not on `PATH`, and the stow calls after it use that prefix's binary), the stow flag table (`--no-folding` for `gpg`, `ssh`, `bin` and `pi`, plus `--ignore='settings\.json'` for `pi`) and the per-package hooks (`gpg`, `ssh`, `antinote`, `pi`, `claude`, `jj`), so any `dotfiles/<app>/` directory is automatically installable. `SRC_DIR` (default `<repo>/dotfiles`) and `TARGET_DIR` (default `$HOME`) come from the `KEY=value` arguments, then the environment, so a test points both at a temp tree. The `pi` and `antinote` hooks call `dotfiles.pi` and `dotfiles.antinote` in process. `tests/lua/packages_test.lua` pins the module. `.dev/sync.lua` is the project's `dev sync` (it wins over the built-in lint-template `dev sync`, so `dev __flags sync` offers none of `--check` and `--yes`): it takes `SYNC_DST` (`user@host`) and `SYNC_PATH` (the remote folder, `dotfiles` by default) from the `KEY=value` arguments, then the environment, and without `SYNC_DST` asks on a terminal and exits 1 without one. It pipes the NUL-separated output of `jj file list` (a `.jj` repo) or `git ls-files -z` into `rsync -azqP --from0 --files-from=-` through `dev.os.capture_input`, then runs `ssh <dst> "cd '<path>' && bash dotfiles/bin/.local/bin/dev install"`, so the remote `dev` finds its project from its working directory. The ssh output goes to a `dev.fs.mktemp` log that a successful sync removes and a failed one keeps (`sync failed; log kept at <path>`, exit 1). `dev sync SYNC_DST=host` and `SYNC_DST=host dev sync` are the same call, and `dev install nvim TARGET_DIR=/tmp/home` installs into a temp tree. `dev install`, `uninstall`, `restow` and `purge` take package names, and the other verbs take only `KEY=value`.

## The guide and scribe commands

### dev guide

A built-in verb in the "Set up a machine or project" group, and machine-local (`--remote` refuses it, and it refuses to run as root). With no question it prints the project's `overview` topic when `.dev/topics/overview.md` exists (rendered like any topic), then the curated `dev help`, as one text that always goes through the pager on a terminal, like the curated view (`DEV_PAGER=0` turns it off). With a question it runs `guide dev --context-dir <root>/.dev/topics -- <question>` from the repo root, so the project's topics are gathered before the rest of the help. It needs the `guide` package installed. The curated `dev help` has no verb-count cap: it is curated by purpose and fits a 50-line screen. `board` is shown under "Share it". The hidden verbs are `bootstrap` (machine-local setup run once), `help` and dev's own `__` helpers, and `tests/dev/guide_test.sh` pins that exact list. `dev help -a` still lists them.

### guide

The `guide <tool> [question]` command. `.local/bin/guide` is a launcher: it finds `luajit` (else prints the install hint and exits 1), makes the work directory (`GUIDE_WORK`, which `main.lua` uses and the launcher's `EXIT`, `INT` and `TERM` traps remove, so `Ctrl-C` leaves none). luajit has no signal handler of its own, so the launcher runs it as a background child and waits for it (a foreground child would defer the `TERM` trap until it ended), the traps end the child and everything it started (a walk down `pgrep -P`) and exit 143 or 130, resolves its own symlink, sets `GUIDE_DEV_LUA` to the `dev` Lua modules (the dotfiles tree beside it, else `~/.local/share/dev/lua`), keeps the caller's `PAGER` in `GUIDE_PAGER`, its `NO_COLOR` in `GUIDE_NO_COLOR` and its `TERM` in `GUIDE_TERM`, exports `PAGER=cat`, `MANPAGER=cat`, `GIT_PAGER=cat`, `NO_COLOR=1`, `TERM=dumb` and `CLICOLOR=0`, and runs `luajit .local/share/guide/main.lua`. `.local/share/guide/*.lua` is luajit: `main.lua` holds the options, the checks, the cache and the scribe calls, `help.lua` parses a help text, `probe.lua` runs tools and the man page through `dev.os.capture_timed`, `tree.lua` reads the top of a help tree, `gather.lua` collects guides, help and the man page, and `check.lua` is the post-check. `main.lua` runs both as `luajit gather.lua MODE TOOL ...` and `luajit check.lua TOOL FILE` (gather exits 3 when the documentation is over the budget). A tool follows the help convention when `<tool> help --topics` exits 0 with at least one `name<TAB>summary` line, and guide then reads its commands from `help -a`. A question goes to `scribe guide-answer --profile guide` (prompts in `dotfiles/scribe/.config/scribe/prompts/guide-*.md`), and the answer is checked against the live help, one `warning:` line per made-up subcommand or flag. Everything guide prints as Markdown (an answer, and the cached or fresh overview) goes through `dev.ui.markdown` with the width capped at 100 when standard output is a terminal and colour is on, decided by `dev.ui.context` over the caller's `NO_COLOR` and `TERM`, read from `GUIDE_NO_COLOR` and `GUIDE_TERM` to survive the launcher's overrides. `progress.lua` draws a status line on standard error, `<label> (<N>s so far)` in dim, under the same rule (standard error a terminal, `GUIDE_NO_COLOR` empty and `GUIDE_TERM` not `dumb`), for each step of a run (reading the help and man page, choosing subcommands, asking the model, checking the answer). It is redrawn at each step, not ticked during one, since the steps block in capture calls, and erased when the step ends or fails, so only the answer stays. The launcher erases it on `INT` and `TERM`. A run with standard error piped, `NO_COLOR` set or `TERM=dumb` draws nothing. A pipe, `NO_COLOR` or `TERM=dumb` print the text unchanged. The post-check warnings are written after the rendered answer, one per line, and the offline help text is not Markdown and stays plain, except that on a terminal with colour `style_help` in `main.lua` bolds each help heading (a line ending in a colon with nothing after it, or all capitals at column zero) and cyans each flag that starts an indented line. It adds colour codes only. `--offline` has `gather.lua offline` print its parts (the guide list, each guide body, the help text) each after a mark line of the control character 0x1e and its kind, which `main.lua` splits. On a terminal with colour it draws the guide list as a `dev.ui.table` with bold names and each guide body through `dev.ui.markdown`, and a pipe, `NO_COLOR` or `TERM=dumb` print the parts joined, with the guide list tab separated and each guide body as written. The man page keeps its own marks: `probe.man_raw` caches `man -P cat` output with the overstrike text as it is, in the entry `man-raw` (an older build's stripped `man` entry is never read, so its page is fetched once), `probe.strip_man` removes the marks as `col -b` does, for the model's documentation, the post-check and a pipe, `NO_COLOR` or `TERM=dumb`, and `probe.style_man` turns `X` backspace `X` into bold and underscore backspace `X` into underline on a terminal with colour, one pair of codes for each run of characters with the same marks. The whole offline text, man page included, goes through `show` once, so the pager takes it as one text. A rendered answer or no-question overview, warnings included, goes through `dev.ui.page` with the caller's pager from `GUIDE_PAGER` (`less -R` when the launcher finds no `PAGER`) when standard output is a terminal and the text is taller than the screen, after the status line is erased; `--no-pager`, a pipe or a short text print it directly. Documentation over `GUIDE_BUDGET` characters (default 60000) takes a second model call, `guide-pick`, to choose the subcommands to read. With no question, a tool with no guides gets a model-written overview cached in `${XDG_CACHE_HOME:-~/.cache}/guide/<tool>/<hash of its version>.md` (`--refresh` rebuilds it, `--offline` skips the model). `probe.help` and `probe.man` keep each help text and the man page in `${XDG_CACHE_HOME:-~/.cache}/guide/<tool>/<hash of its version>.docs/` (`GUIDE_DOC_CACHE` names the directory for the `gather.lua` and `check.lua` children, `probe.use_cache` for the main process), so a second question about one version runs no `--help` probe, only the one `--version` call that makes the key; a probe that hit the time limit is not kept, `--refresh` removes every `.md` and `.docs` entry of the tool, and the `--context-dir` guides and the `help --topics`, `help -a` and `help -k` calls are never cached, since they can change without a version change. Every call to the tool has a time limit (`GUIDE_PROBE_TIMEOUT`, default 3 seconds, and 0 sets no limit, as in GNU `timeout`), runs in its own process group so the limit also stops what it started, and reads no stdin. `dev.os.without_sigpipe(fn)` makes a write to a closed pipe (a pager quit early, scribe exiting unread) fail instead of killing the process. `dev.os.capture_timed(argv, secs, opts)` is the timed call: it polls with a 0.1 second `usleep` (no `timeout` command, and no `sleep` in the loop, to keep `os.execute` from ignoring `SIGINT` while it waits), starts a watcher beside the command that kills its process group and removes the temporary directory when the calling process dies (`Ctrl-C`, `TERM` or `KILL`) or the directory is removed from outside (the guide launcher gives luajit `TMPDIR=$GUIDE_WORK` and removes it with `rm -rf` to end every probe at once, not at the watcher's next poll), sets no limit when `secs` is 0 or less, collects the output, merged with standard error when `opts.merge` is set, takes `opts.input` as standard input (else /dev/null), and returns the exit code, 124 when the limit hit or the command was killed. Tests are `tests/guide/guide.bats`, which put fake tools, a fake `man` and a fake model command first on PATH.

### scribe

The `scribe <kind>` command, the same launcher shape (`SCRIBE_DEV_LUA`). `.local/share/scribe/main.lua` holds the options, the settings and the flow, `profile.lua` walks a profile's `command` and `http` lines in order and returns the first answer, and `backend.lua` makes the curl chat call (the payload built by `dev.json`, only `.choices[0].message.content` read), runs a command backend through `dev.os.capture_timed` with the system prompt and context on its standard input, and cleans the answer (think-blocks, quotes and, for `*name`, `*slug`, `bookmark-*` and `branch-*` kinds, a kebab slug of at most 50 characters). Profiles and prompts are looked up under `SCRIBE_PROFILES` and `SCRIBE_PROMPTS` (default `~/.config/scribe/profiles` and `prompts`). `~/.config/scribe/config` is read as `SCRIBE_NAME=value` lines for any `SCRIBE_` setting (an optional `export`, one pair of quotes around the value) and wins over the environment. Tests are `tests/scribe/scribe.bats`, with a fake `curl` and fake commands first on PATH.
